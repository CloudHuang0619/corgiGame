# Corgidoku 柯基數獨

柯基主題的邏輯益智遊戲。規則與 LinkedIn Queens／Meowdoku 同源，但**沒有數字**：

1. 每個彩色區域恰好一隻柯基
2. 每一橫列恰好一隻
3. 每一直欄恰好一隻
4. 任兩隻柯基不得在周圍八格內相鄰（含對角線）

每一關都保證**唯一解**，可以純靠排除法推出來，不需要猜。

放下的柯基如果不在正解上，會立刻變成紅色叉號並**扣一根骨頭**。每關三根，用完就得重來——所以這遊戲懲罰亂猜，獎勵先把不可能的位置標掉。

## 開始開發

```bash
npm install
npm run dev
```

其他指令：

| 指令 | 用途 |
| --- | --- |
| `npm run dev` | 開發伺服器（<http://localhost:5173>） |
| `npm run build` | 產出 `dist/` |
| `npm run typecheck` | 型別檢查 |
| `npm run levels` | 重新產生關卡表（`-- --count 60` 可指定關卡數） |
| `npm run verify` | 把關卡表每一關重新驗證一次 |
| `npm run capacity` | 量生成器的容量與重複率 |

> Node 已安裝在 `C:\Program Files\nodejs\`。若終端機找不到 `npm`，是該 shell 開啟時還沒吃到系統 PATH，重開一個終端機即可。

## 操作方式

| 手勢 | 行為 |
| --- | --- |
| 點一下 | 空白 ↔ 叉號，來回切換 |
| **快速連點兩下**同一格 | 嘗試放柯基 |
| 從**空白格**開始拖曳 | 沿途塗上叉號 |
| 從**叉號格**開始拖曳 | 沿途擦掉叉號 |

叉號是玩家的推理筆記，必須零成本、可反覆——標錯了要能隨手清掉，而不是只剩「賭一條命放柯基」這一條出路。所以放柯基另外用快速連點觸發，那是不可逆的決定，本來就該是刻意的手勢。

拖曳的模式由**起點那一格的狀態**決定。用起點決定而不是中途切換，是因為一次拖曳如果又塗又擦，手指劃過去的結果會變得無法預期。

判定「快速」的時間窗是 350 毫秒，寫在 `src/core/game.ts` 的 `DOUBLE_TAP_MS`。實機錄影量到玩家兩次點擊的間隔是 100–166 毫秒，350 留了兩倍餘裕。這個門檻放在 UI 層而不是核心——遊戲規則不該知道玩家點得多快，核心只收到「這一下要切叉號還是要放柯基」。

> 這裡跟規格書刻意分歧。原版是三態循環（空白 → 叉號 → 柯基），不設 double-tap 判定；但那樣就沒辦法區分「取消叉號」與「放柯基」。

輸入用指標事件自己配對 `pointerdown`／`pointerup`，不用 `onClick`。觸控裝置上「一次手勢 = 一次 click」沒有保證，瀏覽器在 `touchend` 之後還會補送相容用的 mouse 事件，某些情況會多產生一次 click，結果一次點擊推進兩個狀態。

## 關卡曲線

線性關卡制，盤面隨關卡變大、需要的推論也變深。開局是**空盤面**，不預先放柯基。

| 關卡 | 盤面 | 需要的推論技巧 |
| --- | --- | --- |
| 1–3 | 5×5 | 只需「某列／欄／區域只剩一格」 |
| 4–7 | 6×6 | 同上 |
| 8–11 | 7×7 | 需要「區域 ↔ 線」交叉排除 |
| 12–16 | 8×8 | 同上 |
| 17 | 9×9 | 同上 |
| 18 以後 | 10×10 | 基礎規則推不完，需要試誤 |

難度不是憑感覺標的，是用 `analyse()` 這個推論引擎**實際跑一遍**量出來的。目前共 30 關，全部通過 `npm run verify`。

## 計分與回饋

第 k 隻柯基成功放下時得 `576 + 96(k−1)`，累計 `576n + 48n(n−1)`。常數與公式是從實機錄影的分數變化逐格反推的，在 9×9 與 10×10 兩關都相同，所以獎勵只跟「第幾隻」有關，跟盤面大小無關。失誤不影響分數。

畫面上的分數刻意**落後一次獎勵**：`+N` 飄字還在飛的時候分數欄維持前一個值，飄完才補上。這是原版的節奏。

連續放對 3 隻起開始出現稱號（Nice / Great / Perfect / Excellent / Amazing / Unbelievable），失誤會讓連擊歸零。

### 通關慶祝序列

結算拆成四拍依序播放，而不是一次全丟出來——每一段獎勵被單獨看見一次，比全部擠在同一個對話框裡有份量：

| 時點 | 內容 |
| --- | --- |
| +0.0s | 分數跳到最終值，分數處噴發星光 |
| +0.8s | 生命藥丸淡出，骨頭入帳藥丸由 0 滾到剩餘數 |
| +1.6s | 深色吐司「思路敏銳，幾近完美。」 |
| +3.2s | 彩帶 + 慶祝標題 + 下一關 CTA |

評價分級依剩餘骨頭數：三根全留是「無懈可擊」。原版整段約 20 秒，中間夾了排行榜浮層與插頁廣告；那兩塊屬於後端與變現，這一版沒有，所以壓縮成 3.2 秒。

星光與彩帶都是每一片自己帶 `--dx`／`--drift` 之類的自訂屬性，共用同一組 keyframes——幾十片各自不同的落法只需要一段 CSS 動畫。

## 生命與存檔

每關三根骨頭。放下的柯基不在正解上就會**當場被拒絕**、變成紅色叉號並扣一根，扣完這一關重來。紅叉不能點掉也不能復原掉——命已經扣了，痕跡就該留著，而且那格「這裡不可能」的資訊本身有用。

存檔分成三份獨立的鍵，因為生命週期完全不同：

| 鍵 | 內容 |
| --- | --- |
| `corgidoku.profile.v2` | 目前關卡、暱稱、頭像、骨頭總數、各關最佳成績 |
| `corgidoku.settings.v1` | 音訊開關、圖案模式、語言、慢速播放 |
| `corgidoku.session.v1` | 進行中的盤面、已放的柯基、剩餘生命、分數、連擊 |

進行中的存檔只留會變動的欄位，盤面資料（區域配置與解答）仍從關卡表取——這讓存檔小很多，也避免關卡表更新後讀到舊盤面。通關或失敗就清掉。

全部包在 try/catch 裡：無痕視窗、瀏覽器封鎖網站資料、或 Capacitor 的 WebView 設定不同時，存取都可能直接丟例外。存檔失敗不該讓遊戲當掉。

## 測試工具

正式流程沒有復原、看答案與選關卡——原版是線性關卡，首頁 CTA 永遠指向下一個未通關的關卡，沒有跳關的入口。這些只是開發時要驗證盤面用的，所以放在**遊戲設定 → 測試工具**，主畫面保持乾淨。

| 工具 | 用途 |
| --- | --- |
| 慢速 ×3 | 柯基動畫放慢三倍，用來逐格檢查對齊 |
| 復原 | 退回上一步（紅叉不會被抹掉） |
| 看答案 | 攤開正解。看過就不算通關、不記成績 |
| 選關卡 | 直接跳到指定關卡 |
| 計時 | 顯示本關經過時間 |

計時目前不放進 HUD，是為**對戰模式**預留的基準。

慢速播放的作法是把動畫時長寫成 `calc(Xms * var(--sprite-speed))`，切換只改一個 CSS 變數就整批生效，不必把速度一路傳到最底層的元件。段落接力靠 `animationend` 觸發，事件會在放慢後的實際時間點才發生，接力順序自動跟著慢下來。

## 柯基的美術與動畫

盤面上的柯基會播三段動畫，播放順序是 `START →（IDLE → LOOP）→（IDLE → LOOP）→ …`：

| 段 | 排版 | 影格 | 長度 | 內容 |
| --- | --- | --- | --- | --- |
| START | 8×1 | 8 | 0.5s | 從窗台下方升起、吐一下舌頭。放下柯基時播一次 |
| IDLE | 8×2 | 16 | 1.0s | 待機、眨眼 |
| LOOP | 8×2 | 16 | 1.2s | 往上嗅、轉頭側嗅、回正 |

三段都約 16 fps。`public/sprites/` 底下的三張不是手工放進來的，是由 `art/raw/corgi-all.png`（8 欄 × 5 排 = 40 格的單張素材）切出來的：

```bash
python scripts/normalize-sprites.py --single art/raw/corgi-all.png
```

**三段畫在同一張圖上是關鍵**。分三次產的素材比例會不一致，播放時柯基就忽大忽小；同一張圖裡的比例天然一致。而且素材每一格都畫了「窗台」那條橫木，切割時就以它為錨點對齊——那是所有影格共有、偵測誤差只有 ±1 px 的特徵。角色本身會上下移動（登場時從窗台下升起），不能拿來對齊。

> 用格線切格對齊會失敗：實測這張素材五排的窗台在 y=194/379/562/734/898，排距是 185/183/172/164，並不等分。以格線切出來的格子高度與原點都不同，窗台在格內的相對位置就跟著跑，播放時看起來就是角色一直上下抖。改用窗台錨點後，40 格的窗台落在 y=228~231，只差 3 px。

素材規格與可直接貼給圖像模型的提示詞在 `art/PROMPT.md`。**檔案不存在時會自動退回 `src/ui/CorgiDrawing.tsx` 的手繪 SVG**，遊戲照常能玩，所以美術與程式的時程可以分開。要驗證播放機制，可以先產生帶編號的測試圖：

```bash
python scripts/make-test-sprites.py         # 產生測試 sheet
python scripts/make-test-sprites.py --clean # 刪掉，恢復手繪備援
```

逐格播放用 CSS `steps(N, jump-none)`，走合成執行緒，求解器在算的時候也不會掉格。多排的 sheet 用兩條動畫疊起來：橫向走完一排、縱向再換排。`jump-none` 不能省——細節見 `src/ui/CorgiSprite.tsx` 的註解。排版由圖檔長寬比自動推算，不必在程式裡寫死欄數排數。

## 用手機玩

`vite.config.ts` 裡設了 `server.host = true`，dev server 會綁 `0.0.0.0`，同一個 Wi-Fi 下的手機可以直接連：

1. 電腦上跑 `npm run dev`
2. 查電腦的區域網路 IP：`ipconfig`，找「IPv4 位址」（換網路會變），或直接看 Vite 啟動時印的 `Network` 那行
3. 手機瀏覽器開 `http://<那個IP>:5173`

需要電腦開著、dev server 跑著、兩台在同一個 Wi-Fi。Windows 防火牆第一次可能會跳出詢問，要允許 `node.exe` 的連入連線。

樣式已針對觸控處理過：關掉雙擊縮放、關掉連點反白、hover 效果只在有滑鼠時套用、盤面用 `touch-action: none` 讓拖曳不會變成捲動頁面、並套用 safe-area 避開瀏海與底部手勢條。

> 想要「隨時能開、不必開電腦」，下一步是部署到 Vercel／Netlify 並加上 PWA，手機就能加到主畫面、離線遊玩。真正上架 Google Play 需要 Android Studio；iOS 則必須有 Mac 與 Apple 開發者帳號。

## 關卡生成器怎麼運作

隨機畫色區再檢查有沒有唯一解是行不通的——實測 400 次只有 1 次會是唯一解。所以流程是**先有答案，再長出題目，最後修**：

1. **隨機挑一組合法解**。因為每列每欄各一隻，解必然是一個排列 `perm[row] = col`；規則 4 在排列下等價於「相鄰兩列的欄差 ≥ 2」。搜尋空間因此從 C(N², N) 縮到 N!，9×9 也能即時跑完。
2. **洪水填充長出區域**。以解的每一格為種子，偏袒面積小的區域先長，避免長出「一格區 + 巨獸區」。
3. **迭代修復成唯一解**。找出一組不是正解的解 S2，挑一格「S2 有、正解沒有」的位置，把它改劃給隔壁區域——那格搬進去之後，隔壁區在 S2 裡就變成兩隻柯基，S2 因此失效。被搬動的格子保證不是正解的柯基，所以正解完全不受影響。重複到唯一解為止。
4. **評難度**，不符關卡曲線的目標等級就換一張。

生成吃一個亂數種子，**同一個 seed 永遠產出同一張盤面**。這點是為對戰模式鋪路的：伺服器只要送一個 seed，雙方就能各自算出同一張題目，不必傳整張盤面。

`npm run capacity` 會量各種盤面的產出量與重複率。最吃緊的是最小的 5×5 ——
它的解空間只有 14 種合法排列，實測要湊滿 300 張不重複的盤面會撞到 18 次重複、
1003 次生成失敗（多數是難度不符目標而被丟掉）。盤面越大空間成長得極快，
之後的關卡不必擔心撞題。

## 放置驗證：兩層

這是跟一般 Queens 變體最大的差別。引擎手上有答案，會**即時比對**：

1. 先看有沒有跟既有柯基牴觸 → 能明確指出違反哪一條規則
2. 再比對是不是正解的格子 → 沒有規則可指，只能說「不對」

第二層的存在有直接證據：空盤面上放第一手也可能被拒絕扣命，那時不可能有任何規則衝突。因此玩家不可能走到「合法但推不下去」的死路，零失誤通關才有意義。

第一層的偵測已經實作（會回報違反哪一條規則，對應的規則卡會高亮），但它的專屬回饋——金色衝突外框、大紅叉放大動畫——尚未做，目前兩種失誤共用同一種呈現。
