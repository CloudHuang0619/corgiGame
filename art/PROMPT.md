# 柯基動畫素材：產圖規格

這份是給圖像生成模型（Gemini / ChatGPT 等）的指示。直接複製「提示詞」那一段貼過去即可。

## 為什麼要一張畫完

早期的三張素材是**分三次產的**，每一次的角色比例與裁切都不同：

| 段落 | 原始單格 | 柯基在格內的高度佔比 |
| --- | --- | --- |
| START | 362×339 | 83% |
| IDLE | 181×194 | 96% |
| LOOP | 362×181 | 60% |

播放時三段接力，柯基就會忽大忽小、位置忽高忽低。後製只能逼近，不能修好 ——
因為 LOOP 的身體在原圖裡本來就被裁掉比較多，那些像素不存在。

**三段畫在同一張圖上就沒有這個問題。** 同一張圖裡的角色比例天然一致，
而且如果每一格都把「窗台」畫出來，那條線就是最可靠的對齊基準。

> 目前使用中的 `art/raw/corgi-all.png` 就是這樣產的：8 欄 × 5 排 = 40 格，
> 每格都有窗台，比例完全一致。切割與校正一行指令就完成。

## 提示詞（直接複製這一段）

```
請畫一張柯基的 sprite sheet（逐格動畫表），用於手機益智遊戲。

【畫面內容】
一隻柯基趴在窗台上往外看：只看得到頭、胸口和搭在窗台邊緣的兩隻前腳，
身體下半部被畫面下緣切掉。正面視角。

【畫風】
手繪水彩風，柔和的暖橘與奶油白毛色，細的暖棕色描邊（不要粗黑框），
小圓點眼睛不加高光，表情溫和。整體乾淨、討喜、貼紙感。

【版面：這是最重要的部分，請嚴格遵守】
- 一張圖，8 欄 × 5 排 = 40 格，由左至右、由上而下依序排列
- 每格都是正方形，且大小完全相同
- 整張圖背景完全透明（PNG-32），不要白底
- 不要畫任何格線、外框、編號、標題或說明文字
- 圖片邊緣要切齊格線，四周不留多餘空白
- 建議尺寸：每格 192×192，整張 1536×960

【一致性：這是第二重要的部分】
- 40 格裡的柯基必須是「同一隻、同一個比例」，頭的大小在每一格都一樣
- **每一格都要把窗台那條橫木畫出來**，而且高度固定在同一條水平線上
  （這條線是程式對齊用的基準，缺了就只能靠猜）
- 柯基的左右位置固定置中，不要有格與格之間的左右漂移
- 只有「動作」在變，「取景」不要變

【40 格的內容，依序】
第 1 排（第 1–8 格）　START（登場）
  柯基從窗台下方升起：第 1 格只露出兩個耳朵尖，逐格往上升，
  到第 5 格露出完整的頭與兩隻前腳搭上窗台，第 6–8 格開心地吐一下舌頭。

第 2–3 排（第 9–24 格）　IDLE（待機）
  幾乎不動的呼吸循環：胸口極輕微起伏，中間眨一次眼。
  第 24 格要能無縫接回第 9 格。

第 4–5 排（第 25–40 格）　LOOP（嗅聞）
  第 25–30 格：抬頭往上嗅，鼻子微微抽動。
  第 31–36 格：頭轉向側邊嗅。
  第 37–40 格：頭轉回正面，回到與第 9 格相同的平靜姿勢，才能接回 IDLE。

【再次強調】
不要格線、不要編號、不要文字、背景透明、每格等大、
柯基比例與窗台高度在 40 格中完全一致。
```

## 收到圖之後

1. 把檔案存成 `art/raw/corgi-all.png`
2. 跑分割與校正：

   ```bash
   python scripts/normalize-sprites.py --single art/raw/corgi-all.png
   ```

   格線是靠內容帶自動偵測的，不必指定欄數排數。腳本會印出偵測到幾欄幾排，
   對不上就會直接報錯而不是默默切歪。

3. 確認 `src/ui/sprites.ts` 的 `frames` 與實際格數一致（目前 8 / 16 / 16）
4. 段落的排數切分寫在腳本的 `SEGMENTS`，版面改了要跟著改

## 驗收清單

拿到圖先檢查這幾項，任何一項不過就重產，不要勉強後製：

- [ ] 背景是透明的（不是白色）
- [ ] 沒有格線、編號、標題
- [ ] 每格等大、正方形，邊緣切齊
- [ ] 40 格數量正確
- [ ] 每一格都有畫窗台
- [ ] 隨便挑三格疊起來看，柯基的頭一樣大
- [ ] 窗台那條線在每一格都在同一高度

## 如果模型做不到一張 40 格

退而求其次可以分三次產，但**每次都要附上同一張參考圖**（例如第一次產出的
IDLE 第一格），並在提示詞加上：

```
請嚴格參照附圖的柯基：同樣的比例、同樣的頭部大小、窗台在同樣的高度。
只改變動作，不要改變取景與大小。
```

分開產的素材要用不帶 `--single` 的模式校正，那條路徑會嘗試跨 sheet 統一縮放，
但只能逼近 —— 實測 START 與 IDLE 可以對齊，LOOP 因取景不同仍有約 11% 落差。


## meadow.png — 盤面底下的草地

疊加型盤面的兩個缺角會露出草地。素材是 `art/raw/meadow.png`（1254×1254），
壓成 `src/assets/meadow.webp` 才進打包：

```bash
python -c "from PIL import Image; Image.open('art/raw/meadow.png').convert('RGB').resize((384,384), Image.LANCZOS).save('src/assets/meadow.webp','WEBP',quality=78,method=6)"
```

2731 KB → 21 KB。384px 就夠：缺角只有 3×3 格 ≈ 114px，三倍解析度也才 342px。

放在 `src/assets/` 而不是 `public/`，是因為 CSS 裡用不了 `import.meta.env.BASE_URL`；
交給 Vite 處理才會依 `base` 改寫路徑，Capacitor 的 `file://` 與 Pages 的子路徑才都找得到。

### 產這類素材的提示詞要點

三件事每次都要寫進去，否則模型會自作主張：

1. `No text, no labels, no captions, no frames` —— 不然會多出「Frame 1」之類的裝飾字
2. `seamless tileable` 要明講兩個方向怎麼接，只寫 seamless 常常還是給你有邊界的圖
3. 要去背就寫 `flat solid magenta #FF00FF`，不要寫 transparent —— 模型不會輸出 alpha

另外：**不要叫模型產逐格動畫**。它維持不了跨格一致性（花的位置會跳、葉片形狀會變），
播起來是閃爍不是動畫。會擺動的東西產一張就好，動態交給 CSS transform —— 這個專案的
星光與彩帶就是這樣做的。柯基之所以需要 40 格逐格圖，是因為跑步循環真的做不出來。


## grass.png — 會擺動的草叢

`art/raw/grass.png`（1254×1254，**本來就帶 alpha**，不用去背）。內容只佔畫面 5.5%，
而且根部剛好貼齊底邊 —— 正好可以繞著根部旋轉。裁掉空白再壓縮：

```bash
python -c "
from PIL import Image
import numpy as np
im = Image.open('art/raw/grass.png').convert('RGBA')
a = np.array(im); ys, xs = np.where(a[:,:,3] > 8)
c = im.crop((xs.min(), ys.min(), xs.max()+1, ys.max()+1))
h = 220; w = round(c.width * h / c.height)
c.resize((w, h), Image.LANCZOS).save('src/assets/grass.webp','WEBP',quality=86,method=6,exact=True)
"
```

299 KB → 23 KB。

**擺動不是逐格圖，是 CSS 繞根部旋轉**（`transform-origin: bottom center`）。
每一叢的位置、大小、擺幅、延遲都由座標推導 —— 不用亂數，亂數會讓每次重繪都跳位置 ——
所以共用一組 keyframes 就能有幾十種不同的擺法，也不會整片草同步擺動。
`transform-origin` 一定要在底部：設在中心會變成整叢平移，一眼就假。
